# 第六阶段：远程游戏截图

2026-09-12：实现与自动化验证完成。最初在游戏关闭时使用 Windows 原生编码器生成的确定性夹具验证，下述自动化结果不等于实机捕获。用户随后启动游戏，已完成两档画质、保存、后台遮挡、连续捕获、预览缩放和断开／重连检查，详见 [实机联调](PHASE6_LIVE_INTEGRATION_2026-09-12.md)。

## 已实现

- 主窗口顶部相机按钮和主菜单打开同一个截图窗口。手动单次截取、取消、进度、重新截取、适应窗口、100% 原尺寸、缩放及本地 JPEG 保存；中英文即时切换。
- 标准档最长边 1920 像素、JPEG 质量 0.80；清晰档最长边 2560 像素、质量 0.90；小画面不放大。这是初始档位，画质和速度仍需实机确认。
- 预览保留拍摄时间、尺寸、字节数和原始角色／所属服务器。断线、登出、换角色或重新登录后标为旧画面，允许保存；旧响应不能替换当前预览。关闭截图窗口清理图片与请求，主应用退出同时关闭截图窗口。
- 旧插件未声明截图能力时提示升级，离线时提示连接游戏。截图不写入聊天历史、不自动保存。

## 捕获与传输

插件在 `UiBuilder.Draw` 中安排一次主视口捕获，包含游戏及 Dalamud 界面；异步取得纹理后缩放、转为不透明 JPEG 并释放资源。使用本机 SDK 的 `ITextureProvider.CreateFromImGuiViewportAsync`、`CreateFromExistingTextureAsync` 与 `ITextureReadbackProvider.SaveToStreamAsync`。已检查本机实现和编译兼容性，并在后续实机联调中验证真实帧。[捕获接口](https://dalamud.dev/api/Dalamud.Plugin.Services/Interfaces/ITextureProvider/)、[导出接口](https://dalamud.dev/api/Dalamud.Plugin.Services/Interfaces/ITextureReadbackProvider/)

复用现有加密 TCP 连接，追加能力字段、偏好和消息编号，保留原有编号。请求和每个分片携带请求 ID、角色标识及登录轮次；数据含捕获时间、尺寸、格式、总字节数、分片索引／数量与 SHA-256。完整组装后校验摘要和 JPEG 头中的尺寸，再交给 Windows JPEG 解码器；解码器尺寸也必须一致。

| 边界 | 当前限制 |
| --- | --- |
| 插件并发 | 所有连接合计一张捕获／传输；接受请求至少间隔 2 秒 |
| 原始视口 | 每边最多 8192，合计最多 33,554,432 像素 |
| 压缩图片 | 最多 4 MiB，编码流写入时即限制大小 |
| 分片 | 数据 48 KiB；序列化消息最多 64 KiB；最多 86 片 |
| 图片占用发送队列 | 入队时队列最多 4 包／128 KiB，包含正在发送的包；聊天继续使用原有预算 |
| 捕获等待 | 10 秒取消；渲染任务迟到后释放纹理 |
| 捕获与传输 | 插件总计 30 秒取消；客户端最多等待 35 秒 |

图片分片之间让出执行时间；队列繁忙时短暂等待并受总超时限制。相同重复分片忽略，冲突重复、元数据改变、摘要错误、越界或归属错误均拒绝。缺片不发布图片，等待超时或取消后释放组装状态。连续截图已完成短时现场测量；慢连接和 GPU 纹理释放的专项归因仍未实测。

## 自动化验证

- 通用回归 52 组通过：原有聊天／历史／好友／通知／卡片，以及截图协议、乱序组装、预算、并发／登录取消和队列背压。
- 截图 WinUI 流程 31 项通过：真实加密回环 TCP、Windows JPEG 编解码、反序分片与重复、画质请求、预览／缩放、逐字节保存验证、即时中英文、旧插件、取消／迟到数据、角色及登录轮次隔离、关闭窗口、登出、网络 EOF 与主应用退出。夹具为 1280 × 720，约 404 KiB。
- 原有聊天桌面流程 87 项通过，另有完成标记；包括消息虚拟化、历史、好友、会话和通知。
- 实际插件 DLL 入口 5 项通过：14 个注入服务、300 个清空世界行的模拟登出帧和登出读取保护、开发清单及符号文件。
- 中英文各 510 个资源键一致；插件和正常入口桌面应用 Debug 编译通过。保留已有 Hook／可空性／依赖与 WinUI 发布配置告警。

复现命令见 [测试说明](../tests/README.md)。本机截图测试结果及中英文界面图在 `artifacts/phase6/smoke/`，原有聊天测试结果在 `artifacts/phase6/chat-smoke/`；这些生成文件不纳入 Git。
