# 第四阶段：事件、通知及登出修复

本地分支 `feature/workbench-foundation`，2026-09-11。本轮包含插件事件协议、桌面事件页、通知规则、点击路由，以及用户报告的登出异常修复。尚未发布正式安装包。

## 使用方式

左侧“事件”可按角色／连接与事件类型查看，默认每页 100 条，可加载更早记录。页面在前台阅读时将已显示记录标为已读；侧栏显示未读数量。新事件到达时可点击“查看最新事件”。

“设置 → 通知”提供排本、收到悄悄话、关键词、异常断线、角色上下线、地点变更的独立开关，以及声音、免打扰和定时免打扰。定时免打扰使用电脑本地时间，支持跨午夜；起止相同表示全天。“发送测试通知”会生成本地测试事件，并遵循免打扰规则。

| 场景 | 默认行为 |
| --- | --- |
| 排本就绪 | 提醒；超过 45 秒的事件仅保留记录 |
| 收到悄悄话／命中关键词 | 对应会话或频道未在前台阅读最新消息时提醒 |
| 自己发出的悄悄话 | 不提醒，即使命中关键词 |
| 登录、登出、切图 | 记录；提醒默认关闭 |
| 主动断开、首次连接失败 | 不发异常断线提醒 |
| 已建立连接异常终止 | 同一连接只记录并提醒一次 |
| 历史补发、重复事件、旧登录轮次的排本 | 不重复弹窗 |
| 免打扰 | 关闭弹窗和声音，继续记录事件；结束后不补弹 |

同一会话的连续消息汇总 2 秒，后续提醒间隔至少 10 秒。声音通常至少间隔 5 秒，排本就绪可优先发声，声音总开关仍有效。通知中保存来源、角色、消息／事件 ID 和私聊对象；旧角色的消息打开只读历史，不改变当前连接或发送目标。窗口最小化时先恢复。

## 协议与持久化

- 追加 `ServerOperation.GameEvent=15`、`ServerCapabilities.GameEvents`（MessagePack key 9）和 `ClientPreference.GameEventsSupport=5`。旧端不协商则不发送事件。
- 事件携带服务 ID、运行 ID、事件 ID、角色、登录轮次、类型、UTC 时间、过期时间及名称／数据 ID；插件事件限定为排本、登录、登出、切图，单包最多 4 KiB。桌面会检查能力、服务／运行归属、身份和数据边界。
- `IClientState.CfPop` 的上游实现通过 `Task.Run` 调用订阅方。回调只将托管元数据与不可变登录上下文写入容量 8 的线程安全队列；主线程取出时核对角色和登录轮次，再创建事件。网络线程不读取游戏对象。[Dalamud ClientState 源码](https://github.com/goatcorp/Dalamud/blob/master/Dalamud/Game/ClientState/ClientState.cs)
- SQLite schema 升至 4；迁移前创建 `before-v4-*.bak`，保留原消息、备注、书签、会话和好友记录。事件按连接与角色分区，用稳定 ID 去重，分页使用毫秒时间和 ID；已读状态持久化。
- 事件保留时间沿用历史设置；关闭本地历史后只保留本次运行最多 500 条事件。只有连接期间收到的游戏事件会记录，不补拉断线期间的事件。清理后的持久记录不会由内存缓存重新出现。
- Windows 通知使用 Windows App SDK 的注册、展示和激活接口，注册在读取启动参数之前完成。横幅使用 C1 图标。[Microsoft 通知接入说明](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-quickstart)

## 登出异常

用户提供的 `2026-09-10 23:43:10.840` 日志确认调用链为：

```text
System.InvalidOperationException
Lumina.Excel.RowRef<T>.get_Value()
XIVChatPlugin.Server.CurrentIdentity()
XIVChatPlugin.Server.RefreshGameContext()
XIVChatPlugin.Server.OnFrameworkUpdate()
```

登出／关游戏时，世界行引用可能先清空，而 `PlayerState.IsLoaded` 仍为 true。原来每帧直接读取 `HomeWorld.Value`，因此连续报错。

现在同时检查登录状态、加载状态、ContentId、姓名和可用母世界行；失效时返回无角色。登出事件到达后锁定为无角色，直到下一次登录事件才解除，避免游戏状态尚未清空时重新取得旧角色。玩家资料广播也检查母世界／当前世界的可空行引用，切图地点采用可空引用；资料尚未完整时留待下一帧重试。登出清除待发资料，停止后框架回调立即返回，未登录时不再刷新原生聊天频道。

`PluginLoadRegression` 对真实编译 DLL 注入登出状态：已登出但仍加载、已登录但未加载、两个标记均为 true 但世界引用已清空。身份与玩家资料读取各连续执行 300 次，均安全返回 null；没有用顶层异常吞噬掩盖问题。

## 验证结果与范围

- 41/41 组通用回归通过，新增通知规则、合并／限流、免打扰时间边界、激活参数、协议验证、事件迁移／保留／分页／已读，以及后台排本队列并发和登录隔离。
- 87 项 WinUI 检查通过（另有完成标记）。加密的本地模拟服务器覆盖真实接收路径、私聊合并、前台阅读抑制、关键词频道标志位、发出私聊排除、DND／过期排本／重复事件、错误运行 ID、旧登录轮次、异常与主动断线、事件定位、旧角色只读路由、缓存清理及中英文通知设置。
- 真实插件入口与登出引用回归通过；插件 Debug 构建无错误，保留 7 个既有告警。正常入口桌面 Debug 构建无错误，保留 3 个既有发布配置告警。
- 国际化审计通过：中英文各 395 个键，无重复、空值或格式占位符差异。
- 正常客户端已运行“发送测试通知”：Windows 展示 API 返回有效 ID，界面报告已发送；本地事件页显示测试事件、角色、时间，阅读后未读数归零。通知设置与事件页完成可视检查。

未完成的现场验证：游戏在修复期间已关闭，尚未用新 DLL 再执行真实登出／关闭游戏；未触发真实排本、登录和切图来验证事件来源。当前自动化未取得可操作的 Windows 通知中心窗口，因此不能将横幅实际出现、系统声音、点击系统通知或关闭客户端后的系统唤回标为已实测。程序内路由与参数解析检查不替代这些现场检查。
