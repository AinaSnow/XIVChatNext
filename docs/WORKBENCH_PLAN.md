# XIVChat Next：插件优化与客户端工作台升级

## 1. 目标与默认行为

保留 WinUI 3 和 Dalamud 架构，将客户端升级为统一侧栏工作台，插件提供消息、事件和结构化游戏数据。

- 插件端完成聊天处理优化、频道过滤、队列限制、设置整理、事件通知和游戏卡片升级。
- 客户端增加独立会话、Lodestone 头像、物品与地点收藏、聊天小窗、历史时间线。
- 历史默认本地保留 90 天，可设置永久保存或关闭；收藏、书签及其来源消息不自动清理。
- 会话、未读和历史按自己的角色隔离；收藏可以跨角色查看，始终标明来源。
- 同时保留一个活动游戏连接。关闭主窗口保留聊天小窗，最后一个聊天窗口关闭后退出；菜单“退出”关闭整个应用。
- 不包含 AI 摘要、翻译、云同步、市场价格、自动游戏操作和桌面反向打开游戏地图。物品获取来源仅使用本地游戏数据；头像使用 Lodestone。

## 2. 共用数据与协议

- 使用 `Microsoft.Data.Sqlite`，在用户本地应用数据目录保存消息、会话状态、收藏、书签、备注、事件、头像映射和窗口布局；配置 JSON 继续保存设置。
- 将连接和消息处理移至应用级服务，主窗口、小窗、搜索和通知共享状态，关闭主窗口不影响接收。
- 数据库采用后台单写队列和批量事务；历史分页加载并使用虚拟化列表。
- 搜索覆盖正文、人物、物品、地点和备注，支持角色、频道、日期筛选。使用 FTS5 trigram；一至两个字符的中文查询使用参数化子串搜索。[SQLite 文档](https://www.sqlite.org/fts5.html)
- 自动提取的链接随来源消息清理；明确收藏后保留卡片快照、来源消息和备注。已过期的上下文显示清理提示。
- 数据库迁移前备份并在事务内执行；失败时保留原库，允许临时聊天，不覆盖有效数据。

协议采用追加方式扩展 MessagePack 字段和操作码，保留旧字段编号：

- 增加能力协商，只向支持的客户端发送新消息类型。
- 消息增加稳定标识、持久服务实例标识、运行批次、顺序号、所属角色和明确的悄悄话对方信息。
- 新接口覆盖游标补历史、游戏事件、物品详情、装备快照和携带目标／角色校验的发送请求。
- 按消息标识去重，补历史不足时显示缺口。旧端无法确定归属的记录进入“未归属记录”，不强行合并。
- 切换连接或角色后仍能查询原有离线历史。

## 3. 插件端实现

### 性能与设置

- 按游戏数据版本、语言、物品 ID／类型缓存物品、地图和频道格式；同一消息尽量只解析、序列化一次，各连接独立加密。
- 无客户端且关闭历史时跳过聊天解析。历史开关实际控制记录，关闭时清空插件内存历史，容量调整立即生效。
- 频道订阅取历史保存、活动视图和通知规则所需频道的并集，避免关闭窗口导致漏存。
- 每个客户端的发送队列同时限制条目数和字节量；超限时断开慢连接并记录原因，不阻塞游戏主线程、不静默丢弃社交消息。重连通过游标补历史。
- 发往游戏的队列记录来源连接、角色和目标；断线或切角色后取消失效内容，保留发送节流。
- 房屋等状态采用事件触发加低频校验；游戏内存读取留在主线程，网络工作移出每帧回调。
- 设置分为“连接、消息、设备、诊断”，补全中英文。端口点击“应用”后重启；诊断显示监听状态、设备、积压和最近错误。

### 好友列表透传：可行性调查与接入（新增待办）

- 用户补充：旧好友读取曾有问题并已移除。后续只复用协议设计，旧读取代码按待替换残留处理，先清理或隔离旧 Hook，再验证新读取服务。已同步最新 FFCS／Dalamud 参考源码并核对实际安装版本，问题与替换路径见 [好友读取审查](FRIEND_LIST_REVIEW_2026-09-09.md)。
- 调查结论（2026-09-09）：已有可复用的请求／响应链路。`ClientPlayerList`（客户端操作码 6）请求 Friend 类型，插件 `Server.OnReceiveFriendList` 回传 `ServerPlayerList`（服务端操作码 8）。但桌面端 `Connection.cs` 的 PlayerList 分支直接跳过，也未找到发送该请求的入口；因此不能把现有协议视为端到端功能已完成。
- 当前 `GameFunctions.cs` 通过 Hook 捕获好友列表管理器、请求并解析列表，首次使用可能需要先在游戏打开好友列表。旧实现使用手写偏移，读取 `FriendListEntry.ContentId` 后仅用于跳过无效项，未将其装入协议的 `Player` 对象。
- 优先验证与实际 Dalamud／游戏版本匹配的 FFXIVClientStructs 类型接口，替代重复维护的手写布局；上游存在 [InfoProxyFriendList](https://github.com/aers/FFXIVClientStructs/blob/main/FFXIVClientStructs/FFXIV/Client/UI/Info/InfoProxyFriendList.cs)，继承列表提供 `CharDataSpan`、`GetEntryByName`、`GetContentIdForEntry`，条目包含 ContentId、姓名、母世界、当前世界和状态等字段。参见 [InfoProxyCommonList](https://github.com/aers/FFXIVClientStructs/blob/main/FFXIVClientStructs/FFXIV/Client/UI/Info/InfoProxyCommonList.cs)。源码可用性不等于本机版本实测通过。
- 调查初始化与刷新：比较直接读取已加载缓存和经 `RequestData` 请求刷新，验证是否仍需首次打开游戏好友窗口；以完整响应结束为提交点，避免把分块回调中的半份列表发布给客户端。[InfoProxyInterface](https://github.com/aers/FFXIVClientStructs/blob/main/FFXIVClientStructs/FFXIV/Client/UI/Info/InfoProxyInterface.cs) 提供请求及结束回调入口，具体行为须实测。
- 游戏读取与请求调度放在主线程，复制为受管快照后再序列化发送。合并同时请求、设置刷新节流和超时，清理断线等待者，修复现有等待集合跨线程访问及异步回调竞争；区分未登录、未加载、刷新失败、空列表和缓存过期。
- 优先复用旧 PlayerList 协议，以追加字段及能力协商携带好友 ContentId、所属登录角色、请求／快照标识、完整性和更新时间；保留已有 MessagePack 编号，分包遵守消息大小限制。确认完整快照后再替换列表；拒绝属于旧连接、旧角色或旧请求的迟到响应。
- 客户端按自己的角色保存好友状态，提供好友列表、手动刷新、在线状态与更新时间，并能从好友打开或新建固定目标的私聊会话；断线保留可辨认的过期快照，切角色不得沿用上一角色好友。服务端仍校验发送时的活动角色和目标。
- 调查通过唯一的完整姓名＋母世界匹配好友快照，为已确认好友补充私聊对端 ContentId；无匹配或有冲突时保持未知，不错误合并旧历史。Lodestone ID 仍独立查询，不由 ContentId 推算；仅按需为可见好友加载头像，不批量扫描整份好友列表。
- 状态（2026-09-10 更新）：旧读取已移除，新的类型化读取服务、完整分页协议、客户端自动／手动刷新和按角色保存快照已实现。24 项回归与 29 项 WinUI 检查通过；单角色真实游戏自动拉取、手动刷新、重连已验证，完整 42 条与游戏人数一致，身份不完整条目保留并明确标记。实现见 [好友快照接入记录](FRIEND_SNAPSHOTS_2026-09-09.md)，实测和在线状态时效限制见 [游戏联调记录](FRIEND_LIVE_INTEGRATION_2026-09-10.md)。第三阶段继续完成好友界面、会话及头像衔接；以上旧实现描述保留为调查背景。

### 事件与通知

- 使用 `IClientState.CfPop` 接入排本就绪，登录、登出、切图进入事件记录。
- 插件发送游戏事件；桌面端统一处理悄悄话、关键词和连接中断，避免重复提醒。
- 默认提醒排本就绪；悄悄话和关键词在对应会话未被前台阅读时提醒。上下线和切图默认仅记录。
- 主动断开不提醒，同一次异常断线只提醒一次；补发历史和过期排本事件不弹通知。
- 支持分类开关、声音、免打扰和连续消息合并。点击通知定位会话或事件，必要时重新打开主窗口。

### 游戏卡片

- 增加结构化属性，包括参数 ID、数值、NQ/HQ 差值、装备部位、职业／等级要求和魔晶石槽；保留旧字符串兼容展示。
- 使用 Dalamud 的物品类型和品质信息，正确区分普通、HQ、收藏品和任务物品。
- 物品与地点卡片支持复制、收藏和来源跳转；地点保留地图、坐标、名称及分享来源。
- 通过 `IGameInventory` 在登录、换职业和装备变化时更新装备快照。比较基础属性，单独列出镶嵌，不计算战斗收益或等级同步。
- 戒指提供两个当前戒指的对比入口；无法直接比较的部位、武器或特殊装备只并排展示并说明限制。
- 配方显示制作职业、等级、产量、材料数量，材料可继续打开卡片。
- 获取来源展示本地数据能确认的普通金币商店和采集点，包括可确定的 NPC、价格、区域及位置；缺失关联显示暂无数据，不推断掉落或兑换来源。
- 详情按需查询、分页返回并遵守现有包大小限制。客户端按版本和语言缓存；离线展示更新时间，登出后的装备标记为非实时。

## 4. 客户端功能

### 工作台与会话

- 侧栏包含“会话、频道、收藏、历史、事件”，顶部显示连接、当前角色和全局搜索。
- 原标签页迁移为频道视图，保留名称、过滤和 Markdown 设置。
- 悄悄话按“自己的角色＋对方姓名／所属服务器”建立会话，支持置顶、未读、最近消息、备注和草稿；身份不完整时不自动合并。
- 会话发送固定指向对方，服务器校验当前角色。状态仅表示已入队或已交给游戏，正式记录以游戏聊天回显为准。

### Lodestone 头像：自动查找＋手动修正

- 桌面端按“完整角色名＋所属服务器”查询官方角色搜索，仅自动接受唯一且完全匹配的结果。使用所属服务器，不使用跨服访问时的当前服务器。[官方角色搜索](https://jp.finalfantasyxiv.com/lodestone/character/)
- 从结果保存 Lodestone 角色 ID，再读取角色页提供的头像图片地址；不根据 ID 猜测图片 URL。
- 不假设游戏 `ContentId`／`EntityId` 等于 Lodestone ID。头像映射独立保存，不用于合并历史、识别发送目标或验证身份。
- 自己的角色与会话对象均支持头像。优先加载当前可见角色和会话，不扫描整份聊天历史批量请求。
- 提供粘贴 Lodestone ID 或角色页链接、查看已绑定资料、重新查找和解除绑定入口。手动绑定优先，不被自动查找覆盖。
- 本地缓存映射和图片；成功结果超过 24 小时后按需后台刷新，失败结果缓存 1 小时，并提供手动重试。同一角色请求合并，站点请求串行且间隔至少 1 秒。
- 查无结果、结果有歧义、资料不可用、网络失败或页面解析失败时保留旧头像；没有缓存则显示姓名占位头像。头像加载不阻塞消息接收和界面。
- 头像服务由桌面端承担，不给插件游戏主线程增加网页请求。支持关闭在线头像，关闭后停止联网查询。

### 收藏与时间线

- 自动提取物品和地图链接，提供“最近出现”和“已收藏”。
- 物品按 ID、类型／品质区分，地点按地图和坐标区分；相同卡片可以展开多条来源。
- 支持分组、标签、私人备注、搜索和来源跳转；刷新详情不覆盖备注或原始来源。
- 跨角色收藏标明来源，跳转时打开对应角色历史。
- 时间线支持角色、人物、频道、日期、物品、地点组合筛选，关键词高亮、前后文、按日跳转、书签、备注和连续区间选择。
- 沿用现有导出格式，改为数据库查询，支持会话、搜索结果和时间段导出；明确显示离线、缺失和已清理记录。

### 独立聊天小窗

- 会话和频道支持按钮弹出及拖出，同一视图最多一个独立小窗。
- 消息和已读状态共享；草稿、滚动位置、窗口尺寸、位置、置顶及显示设置独立保存。
- 提供“日常社交、副本交流、装修采购”预设和自定义布局。
- 启动恢复布局，显示器或 DPI 变化后修正到可见区域。
- 小窗提供返回主窗口和退出入口；最后一个聊天窗口关闭后保存状态并停止连接，详情窗口不单独维持应用运行。

## 5. 实施顺序与验收

按阶段建立独立 Git 提交：

1. 协议、角色身份、消息标识、SQLite 和应用级共享服务。
2. 插件缓存、过滤、队列限制、历史开关和设置整理；验证好友列表读取、刷新及透传协议。
3. 工作台、会话、好友列表与私聊入口、Lodestone 头像、历史搜索及旧配置迁移。
4. 游戏事件、通知规则、免打扰和点击定位。
5. 游戏卡片、装备对比、配方、获取来源和收藏。
6. 多窗口、布局、导出及整体联调。

验收覆盖：

- 新旧双端交叉连接、重连去重、顺序与缺口；跨服同名、切角色和待发送内容不串记录、不发错对象。
- 90 天清理保留收藏及书签；迁移或写入失败不覆盖有效数据。
- 十万条历史的中文短词、组合筛选、取消查询和分页；一万条数据的列表虚拟化及阅读位置保持。
- 慢连接、队列积压和批量物品链接不造成无界内存或游戏主线程阻塞。
- 好友列表首次未打开／已打开、空列表、离线好友、跨服好友、刷新分块与超时、多客户端同时请求、掉线／切角色和迟到响应；与游戏列表核对完整性及 ContentId，验证旧客户端兼容、好友私聊目标正确、无效字段与头像查找失败可正常回退。
- 头像唯一匹配、同名跨服、手动覆盖、改名／转服后的重新匹配、缓存刷新、限流、断网和页面结构变化；以提供的 `22586842` 链接验证 ID 提取，在线头像验证以页面实际可访问为准。
- 排本、主动断开、异常掉线、免打扰和历史补发符合通知规则。
- NQ/HQ、收藏品、双戒指、不可比装备、配方、多来源和离线快照展示正确。
- 主窗口关闭、小窗退出、显示器移除、DPI 变化和布局恢复不遗留连接或不可见窗口。
- 扩展现有回归和 WinUI 检查，并在实际游戏中验证排本、悄悄话、装备变化及端口切换。
