# 首次启动引导、首页快捷连接与中继范围

状态：2026-09-14 计划已获确认并实现引导、快捷连接及自部署中继接入。最初仅讨论中继，后续授权已扩展为本轮实施。实现和验证结果见 [实施记录](verification/RELAY_SETUP_2026-09-14.md)，实际使用见 [中继指南](user/SELF_HOSTED_RELAY.md)。下方保留设计依据与验收要求。

## 1. 实施前的代码依据

- 客户端已有语言、服务器列表、设备信任和通知设置，可复用现有配置及连接流程，无需修改聊天协议。
- `LocalizationHelper.cs` 已支持跟随系统、简体中文、English。
- 插件默认监听端口为 `14777`，修改端口需要在插件端点击“应用”，会断开当前连接。客户端填写的是目标插件端口，不能代替修改插件监听设置。
- 首页左上角 Logo 在 `MainWindow.xaml` 中是静态图片，旁边菜单已有连接和断开入口。
- `App.LastHost` 仅为本次进程中的会话状态，没有持久保存“上次成功连接”的配置；不能直接拿它作为重启后的快捷连接依据。
- 客户端 `Connection.cs` 使用 TCP 直连。插件 `Relay.cs` 有 WebSocket 中继接入，但桌面端没有对应传输实现，仓库也没有独立中继服务端。

## 2. 首次启动引导

采用四步流程，显示步骤、上一步、下一步，以及“稍后设置，进入离线工作台”。设置页保留“重新运行初始设置”入口。

### 第一步：客户端语言

- 默认跟随系统，另提供简体中文、English，切换后即时更新引导文案。
- 明确此选项影响客户端界面；物品资料语言沿用现有卡片设置。

### 第二步：连接游戏

- 选择“游戏与客户端在同一台电脑”或“连接另一台电脑”。
- 同机预填 `127.0.0.1`、端口 `14777`；另一台电脑要求输入游戏电脑的 IP 或主机名，不沿用回环地址。
- 可编辑连接名称、地址和端口。地址与端口分开保存，端口只接受 1–65535，错误在字段旁说明。
- 提示先在游戏加载插件，并核对插件显示的实际监听端口。非默认端口以用户填写为准。
- 提供连接测试：复用正式加密握手和设备信任流程，不只检查 TCP 端口是否打开。等待信任时明确提示到哪一端确认。
- 区分地址解析失败、连接被拒绝、连接／握手超时、信任未通过、已连接但角色未登录；可取消、修改后重试。
- 测试成功的连接可沿用到工作台，不重复建立第二条连接；首次完成信任后才允许保存为最近成功目标。

### 第三步：通知偏好

- 推荐默认沿用现有行为：排本就绪、未在前台阅读的悄悄话、异常断线开启；上下线和换地图仅记录。关键词提醒复用已有规则，新用户可稍后添加关键词。
- 提供声音开关、免打扰和可选免打扰时段。
- 提供“发送测试通知”，验证横幅、声音和点击返回客户端。系统禁用通知或开启免打扰时说明系统设置入口，不自动改变系统设置。
- 引导中的测试开关使用当前草稿；取消引导时不意外覆盖旧通知偏好。

### 第四步：确认与开始

- 展示语言、连接名称／地址／端口、通知摘要和连接测试结果。
- 提供“保存并连接”或已连接时的“开始使用”，以及“保存，稍后连接”。
- 同页简要告知现有默认行为：聊天历史本地保留 90 天、在线头像可在设置中关闭；不增加强制步骤。
- 保存失败保持当前步骤并允许重试，不标记为已完成。

### 启动与旧配置兼容

- 新增版本化引导状态，区分未开始、暂缓、完成。明确选择暂缓后不在每次启动强制弹窗，首页保留继续设置入口。
- 真正首次启动自动显示；已有有效配置的升级用户保持现有设置，仅给出可忽略的引导入口。
- 在启动写入默认配置之前确定是否为首次启动，避免新建的配置文件让首次引导被跳过。
- 配置损坏、备份恢复先走现有恢复流程，不误判为新用户，不用引导默认值覆盖待恢复配置。
- 引导编辑使用草稿；只有明确保存时才提交所选偏好。设备信任仍按现有独立确认流程保存。
- 引导只出现一个实例，与恢复提示、设备信任、通知激活和窗口布局恢复协调，不重复弹窗或争抢焦点。

## 3. 首页 Logo 一键连接

将现有 Logo 改为保持原有外观的可聚焦按钮，支持鼠标、键盘和读屏。旁边菜单继续提供连接管理与断开操作。

| 当前状态 | 单击行为 | 提示 |
| --- | --- | --- |
| 未连接，有最近成功目标 | 连接该地址与端口 | 连接到“名称 · 地址:端口” |
| 未连接，没有最近成功目标 | 首次用户打开连接引导；已有用户打开服务器选择 | 设置连接／选择服务器 |
| 正在连接或等待信任 | 不创建重复连接；提供可见进度和取消入口 | 正在连接／等待设备确认 |
| 已连接 | 展示当前连接详情及管理入口 | 已连接到“名称 · 地址:端口” |
| 连接失败 | 保留最近成功目标，显示重试和修改连接入口 | 具体失败原因 |

- 新增持久化的最近成功连接记录，保存地址、端口、可选服务器标识和名称；在连接握手、信任和初始化成功后更新，失败尝试不覆盖旧记录。
- “已连接但角色未登录”仍可作为有效连接目标，不以能否发送聊天判断连接成功。
- 不把最后选中的服务器、最后尝试的地址或列表第一项冒充最近成功连接；旧用户首次使用该功能需先完成一次连接。
- 删除被引用服务器时清除关联快捷目标；编辑其地址／端口后等待新地址成功连接再更新快捷记录，不悄悄继续连接被替换的旧地址。
- Logo 单击只在用户点击后发起连接；“启动应用自动连接”作为独立的可选后续设置，不隐含启用。
- 复用当前单连接约束及公钥信任校验，服务器密钥变化时仍需确认，不因为快捷连接跳过。
- 最近目标保存失败应提示未保存，但不拆掉已经成功的游戏连接。

## 4. 中继是什么，是否需要服务端

2026-09-14 后续讨论与实施：用户确认 [中继架构与仓库结构方案](RELAY_ARCHITECTURE_DISCUSSION_2026-09-14.md)，本轮新增独立服务、双端接入、配对、容器部署及单仓第一批整理。

直连路径：桌面客户端 → 游戏电脑上的插件。

中继路径：桌面客户端 → 可共同访问的中继服务 ← 游戏电脑上的插件。中继负责匹配连接并转发协议数据，适用于客户端无法直接访问游戏电脑的网络环境；不替代游戏服务器，游戏和插件仍需运行。

实施前的插件使用固定 Debug/Release 中继地址。本轮已替换为可配置的自建 HTTPS 地址、独立设备注册凭据及一次性邀请，桌面端已接入相同的新 v1 中继；不复用旧公共服务或旧认证码。

- 同机或可直接互通的局域网使用不需要另做中继服务端，首次引导以直连为默认方案。
- 仓库现有独立 ASP.NET Core 服务和 Docker/Compose 部署文件；双端可配置地址并通过邀请配对。
- 首次引导可选择自建中继；必须先配对连接，不能把中继地址填入原 TCP 主机字段代替配对。
- 已实现设备注册和配对、会话路由、认证与撤销、端点 TLS 与原设备信任、心跳重连、有界转发、连接和流量限额；服务不存聊天内容和原始凭据。
- 中继验收需覆盖真实不同网络、认证失败／过期、设备撤销、客户端串线隔离、服务重启、慢连接和截图占用，确认聊天正常转发。完成前不能标记为可发布功能。

## 5. 实施顺序与验收

1. 配置迁移与最近成功连接记录；补齐服务器表单错误提示。
2. Logo 按钮、连接进度／取消／错误提示；验证重启后快捷连接。
3. 四步引导、通知测试、语言即时切换和设置页重开入口。
4. 离线回归及真实游戏／Windows 通知验收，更新使用说明。
5. 中继已按后续授权纳入本轮；其独立构建、容器及协议检查与桌面端分开记录，公网和真实游戏验收仍明确标注。

必要验证：

- 全新配置、旧配置升级、配置损坏／备份恢复、保存失败、暂缓和重开引导。
- 跟随系统／中英文切换、字段错误可见、键盘完成流程和按钮提示。
- 默认与自定义端口、同机和另一台电脑、无效地址、超时、信任拒绝／公钥变化、已连接但角色未登录。
- 连续点击只产生一个连接尝试；取消后迟到结果不覆盖新连接；失败不污染最近成功目标。
- 重启后恢复最近成功地址，删除／修改服务器正确处理关联记录，连接仍遵守单活动连接和角色隔离。
- 通知偏好保存、测试横幅／声音／点击、系统禁用通知及免打扰时的反馈。

本文件最初为规划，现已更新实施状态。测试使用隔离配置和用户授权的远程容器，没有把测试凭据写入正常用户设置；具体通过项和剩余验证以实施记录为准。
