# 好友快照真实游戏联调（2026-09-10）

本次在已登录角色和现有本机连接上验证好友链路，时间均为北京时间。单角色的完整名单、自动请求、手动刷新、落库和 TCP 重连通过；第二阶段其他队列／缓存／设置工作及第三阶段好友界面仍需继续。

## 实测发现与修复

初次请求正常进入原生完成回调，但快照校验失败。仅记录统计的诊断得到 42 条、零 CID 0 条、重复 CID 0 条、缺母世界 1 条、缺姓名 1 条。此前协议要求所有条目同时具备 CID、姓名和母世界，导致这一条目阻止整份名单发布。

在 `Player` 的 MessagePack Key 16 追加 `IdentityUnavailable`，保留游戏提供的 CID 与不完整条目，不编造姓名或世界，也不推断该角色已删除。校验继续拒绝零 CID、重复 CID、过长姓名，以及未明确标记的缺失身份字段；标记必须与字段缺失情况一致。未来好友界面应显示身份不可用，并禁止使用这些条目构造私聊目标、历史身份匹配或头像查询。

菜单文案从含糊的“刷新”改为“刷新好友列表”。插件诊断不输出整份名单、姓名或 CID。

## 验证结果

- 在本次尚未打开游戏好友窗口时，00:35 自动请求成功：42 条完整入库，42 个 CID 均不重复，所属角色与数据库分区一致，登录批次有效。
- 00:35 手动刷新在客户端显示“好友列表已更新：42 人。”；快照 ID 和时间更新，条目内容与前次一致。
- 00:37 打开游戏好友窗口，界面从加载中的 20/200 更新为 42/200，与完整快照人数一致。
- 00:40 主动断开 TCP 连接，00:41 重连后自动请求成功。数据库仍只有该服务源／角色的一行好友快照，共 42 条，包含 1 个身份不可用条目；其余 41 条姓名和母世界有效，时间推进。数据库 schema 为 2，完整性检查为 `ok`。
- 重连后普通聊天和当前角色状态恢复；联调结束时插件已启用，正常桌面客户端保持连接。
- 修复后的通用回归 24/24 通过，增加 42 条中含身份不可用条目的分页往返、未标记缺失字段拒绝及零 CID 拒绝验证。插件与正常桌面入口 Debug 构建均通过，保留已有编译警告。
- 此前隔离 WinUI 冒烟的 29 项检查仍是 2026-09-09 版本的验证结果；本次修复使用上述真实客户端交互验证，没有重新运行该套冒烟。

## 在线状态与待验范围

完整名单不等于所有动态状态同时就绪。第一次快照有 1 条非零状态；游戏好友窗口打开后，在线信息继续更新。00:41 新快照读取到 5 条非零状态，说明后续刷新会读取更新后的原生数据，但本次没有逐条确认所有状态位语义与游戏显示一致。

当前 `Status`、当前世界、职业和地点是原生完成回调时的数据，不保证实时在线状态，也不能将尚未填充的状态直接解释为确认离线。FFCS `AgentFriendlist.RequestFriendInfo` 明确具有单好友在线信息请求入口；当前实现没有批量调用它。第三阶段接入在线筛选前，需要定义未知／过期状态，并验证跨服在线信息的请求、完成时机与限流。

尚未完成真实游戏验收：空好友名单、200 人、多客户端同时请求、登出重登／切角色、原生请求超时后迟到完成和永久不回调的恢复。自动测试已覆盖其中的协议和托管状态机边界，不能替代原生行为验证。未逐项比对全部好友姓名／母世界，也未验证好友私聊和头像功能；这些入口尚未实现。
