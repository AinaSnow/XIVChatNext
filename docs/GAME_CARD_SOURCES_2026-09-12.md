# 游戏卡片数据来源与首批修复

本轮针对“传过来的内容有问题”检查了物品、地图的生成、协议和显示路径。结论是保留当前游戏文件作为数值依据，先修正类型判断、HQ 合并和地图回退，再按数据用途引入外部资料。更换 URL 本身不能解决这些错误。

## 查证与选择

| 来源 | 合适用途 | 使用边界 |
| --- | --- | --- |
| 当前游戏的 Lumina / Dalamud 数据 | 物品 ID、类型、属性、装备要求、地图 ID 与比例 | 与运行中的游戏数据一致；文本使用游戏数据语言。表格基础属性不等于某件实际装备的镶嵌、自定义属性或同步结果。 |
| XIVAPI v2 | 国际服资料补全、按字段查询、素材服务 | 官方服务提供日英德法，不能当作中文源；数值接入应指定版本与 schema。 |
| thewakingsands/ffxiv-datamining-cn | 中文名称、描述和中文资料包的候选来源 | 国服独立版本，不能把其整行数值直接覆盖国际服；应固定提交/版本，以表名＋ID 关联，缺失保留原文。 |
| Waking Sands 地图 | 用户主动打开的外部地图查询 | 显式标为外部资料，不能静默填充历史消息缺失的地图 ID 或比例。 |

依据：

- [XIVAPI 数据版本与语言说明](https://v2.xivapi.com/docs/guides/concepts/)：国际版与中韩版采用不同数据及版本；目前官方 API 只服务国际客户端语言。
- [XIVAPI 版本与 schema 固定](https://v2.xivapi.com/docs/guides/pinning/)及[字段选择](https://v2.xivapi.com/docs/guides/sheets/)：适合按需、有限字段的补充查询。不能用不固定版本的 latest 当作当前游戏事实。
- [中文游戏数据项目](https://github.com/thewakingsands/ffxiv-datamining-cn)：由维护者提供的国服拆包资料，适合作为可追溯的中文资料包来源；本轮没有下载或接入中文数据包。
- [Dalamud ItemUtil 源码](https://github.com/goatcorp/Dalamud/blob/master/Dalamud/Utility/ItemUtil.cs)：收藏品与 HQ 是不同类型，任务物品 ID 保持原值；部分语言的任务物品名称需要使用 Singular。
- [XIVAPI HQ 属性说明](https://github.com/xivapi/ffxiv-datamining/blob/master/docs/ItemStats.md)：HQ 特殊值是普通值之外的增量，应相加。另使用 v2 BaseParam 接口核对了 12=Physical Damage、13=Magic Damage、21=Defense、24=Magic Defense；22 是 Direct Hit Rate，不能误当魔防。

## 已完成

- 新增结构化参数：参数 ID、游戏语言名称、NQ 值、HQ 增量；附装备部位类别 ID、可用职业文本和可否 HQ。物品原有装备等级、品级和魔晶石槽字段继续使用。
- HQ 按参数 ID 合并，包括基础攻击和防御；物理和魔法属性即使数值相同也分别保留。保留负值，避免通过翻译后的名称或数组位置匹配。食物等非装备的效果不当作装备 HQ 加成。
- 客户端优先显示结构化参数，旧消息继续显示原字符串；旧记录中的错误字符串不会被凭空重新计算。协议只追加 TextChunk 的 24、25 字段，旧字段不移动。
- 明确区分普通、HQ、收藏品、任务物品。新消息以插件传来的类型为准；兼容旧编码 ID，任务物品不减偏移；任务物品名称为空时回退 Singular。
- 物品数据附来源、游戏语言、可读取的 ffxivgame.ver 和读取时间。读取不到版本时保持缺失，不借用远端版本；卡片注明基础属性的范围。数据语言与界面语言分别保留。
- 移除地图按 ID 自动向旧 CafeMaker/XIVAPI 接口读取并混合缓存比例的路径；不再为缺少地图 ID 的消息套用玩家当前位置，也不再猜比例为 100。数据不完整时显示缺失说明；有地图 ID 时提供显式外部查询链接。
- 地图坐标优先使用消息内结构化数值，文本解析只兼容旧消息。地图路径校验后才用于素材缓存；CSS 和查询参数使用固定小数格式，不再把图外坐标夹到图边伪造位置。
- 物品名称、描述、属性及地图文字按纯文本编码。两种详情窗口的异步显示都增加请求序号，较早的加载完成后不能覆盖新卡片，也不能在关闭后继续显示。

地图图片与物品图标仍使用既有的远端素材和本地图片缓存；本轮调整的是数值与身份来源，并未把全部素材迁移到本地游戏读取。图片与元数据的完整版本隔离仍需配合后续按需详情协议。

## 验证

- 插件 Debug 编译通过，0 错误，7 个既有告警。
- 通用回归 43/43：新增物品类型、HQ 按 ID 合并、相同双防保留、负增量以及新旧消息读取。
- 独立 WinUI 卡片测试 8/8：真实 WebView 中核对 HQ 总值、旧字符串覆盖规则、纯文本描述、来源信息、打开窗口切换语言、收藏品、任务物品及缺失地图/比例提示。测试使用明确标记的模拟物品，不连接游戏。导出卡片图片并检查了布局。
- 中英文资源各 401 个键；无重复、空值、占位符不一致，静态资源引用通过。
- 最后恢复正常桌面启动入口并重新编译。测试入口仅通过 DesktopCardsSmoke.targets 显式启用。

还需要实机对照：真实 HQ 武器/防具、收藏品与任务物品链接，游戏版本字符串、不同地图楼层和实际坐标。自动化样本不替代这些检查。

## 后续游戏卡片接入顺序

下一步以当前结构化对象作为基础，把完整详情移到按需请求，消息只保留身份及必要的离线快照；按来源、游戏版本、语言、表名、ID、品质分开缓存并展示更新时间。中文资料包先做文本覆盖与原文回查，缺失不补造、不覆盖数值。

之后接入配方与可确认的本地商店/采集关系，以及 IGameInventory 装备快照，再扩展收藏和装备比较。真实镶嵌、自定义装备参数要来自实际装备实例，不能从静态 Item 行推断。本轮未将这些后续功能标为完成。
