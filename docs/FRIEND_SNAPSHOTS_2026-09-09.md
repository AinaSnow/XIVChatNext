# 好友快照接入记录（2026-09-09）

第二阶段好友数据链路已实现，自动测试通过。2026-09-10 已完成单角色真实游戏的自动拉取、手动刷新与重连验证，并修复身份不完整条目导致整份快照失败的问题；详见 [真实游戏联调记录](FRIEND_LIVE_INTEGRATION_2026-09-10.md)。下文保留实现时的测试范围，剩余实测项以新记录为准。

## 实现

- 移除 `GameFunctions` 中三组旧好友签名、Hook、手写条目布局和异步事件链路。
- 新 `GameFriendListReader` 使用已安装 FFCS 的 `InfoProxyFriendList` 类型，框架线程发起 `RequestData`，在完整 `EndRequest` 回调后复制受管快照。不会从网络线程访问游戏指针。
- `FriendListCoordinator` 合并客户端请求，最多排队 256 项、每帧接收 64 项，同一客户端最多一个等待请求。5 秒刷新间隔与缓存复用，10 秒插件超时，断线取消等待者。
- 复用 PlayerList 操作码，追加 ContentId、请求 ID、角色身份、登录批次、快照 ID、时间、分页描述和错误状态。每页最多 32 人、120 KiB，整份最多 200 人；旧字段编号不变。新客户端通过 `FriendSnapshots` 能力位启用。
- 每次登录生成独立批次，防止同一角色重登后接受上次登录的迟到数据。
- 客户端在能力和身份就绪后自动请求，菜单增加“刷新好友列表”。15 秒客户端超时；完整分页校验前不发布、不入库。错误保留旧快照并标记过期，断线保留带原角色身份的过期快照，切换角色或服务源清除不匹配的快照。
- SQLite schema v2 增加 `friend_snapshots`，按服务公钥与自己的角色键分区。迁移前备份、事务内升级，旧时间快照不会覆盖更新快照。遵循客户端现有本地历史存储开关。

完整好友界面、在线筛选、更新时间展示、固定目标私聊和头像衔接属于第三阶段，尚未实现；本次手动刷新通过系统消息反馈人数或错误。
